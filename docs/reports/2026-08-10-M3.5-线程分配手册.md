## 二、分配流程

1. 协调者（本线程）确认任务卡就绪；涉及契约的任务（T-25、T-29）先由协调者更新 contracts.js/API.md/ADR 并通知用户。
2. 用户为每个任务单独创建一个 Codex 线程，粘贴“统一提示词 + 该任务专属提示词”（见下文）。
3. 线程自行创建/使用任务卡中的 worktree 与分支（git 写操作需要真实权限时请用户协助或申请提权）；**不在 main 上直接开发**（T-32 除外）。
4. 线程实现 → `npm.cmd run check`（必须通过）→ 尽量 `npm run smoke`（需真实权限，失败须说明）→ 涉及 UI 尽量 `npm run dev` 目检。
5. 线程更新自己的任务卡状态为“已完成（待协调者验收）”，提交分支；**不合并 main**。
6. 线程把结果发回协调者（/root）：分支与提交号、改动文件清单、check/smoke 结果、UI 目检结论、边界外触碰说明。
7. 协调者验收：核对 diff 边界、解决与 main 的共享文件冲突、合并 main、跑 check（必要时请用户跑 smoke/目检）、更新 PLAN/STATUS。
8. 全部优化任务验收完成后，最后执行 T-32（orchestrator 修复）；修复后是否入库由用户决定。

并行建议：本批次任务大多触碰 `src/renderer/chat.js`、`index.html`、`chat.css`、locales、`scripts/check.js`，**建议一次只跑一个线程（串行）**，避免共享文件冲突；确需并行时由协调者合并冲突，且不要超过 2 个。

要求：
1. 只修改任务卡“涉及文件”列出的内容；其他文件只读；禁止触碰 package.json、package-lock.json、src/shared/contracts.js、docs/API.md、PLAN.md、docs/STATUS.md、AGENTS.md、docs/DECISIONS.md、scripts/orchestrator/**。
2. 若任务卡要求新增/移除契约（如 petAPI.window.minimize、window.setShortcutEnabled），契约文件只读：先检查 docs/API.md 与 src/shared/contracts.js 是否已由协调者冻结，未冻结就停下回报协调者，不要自行改契约。
3. 使用任务卡指定的分支/worktree；不要在 main 上直接开发（T-32 除外）。
4. 实现后用 npm.cmd run check 自检，必须通过；npm run smoke 若因真实用户权限无法运行，说明原因并请协调者/用户复核，不得谎报通过。
5. 涉及 UI 的改动，如能运行 npm run dev 请自行目检并在任务卡完成记录写清；不能运行则注明“待人工目检”。
6. 完成定义：更新自己的任务卡状态为“已完成（待协调者验收）”，提交到分支，不要合并 main。
7. 完成后立即把以下内容发回协调者（/root）：分支与提交号、改动文件清单、check/smoke 结果、npm run dev 目检结论、边界外触碰说明。等待协调者验收后再进行下一步，不要开始其他任务。
