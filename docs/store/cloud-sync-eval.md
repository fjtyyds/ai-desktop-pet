# 云同步技术评估与 ADR 草案（T-46）

> 状态：评估完成（2026-08-11）；**不实施**。产出加密方案、候选服务、月成本估算与 ADR-035 草案（Proposed）。

## 1. 背景与需求

- 商业化方案（ADR-032）将“云同步 100MB”列为 Pro 权益；目标：跨设备同步设置/人格/长期记忆/对话历史（可选皮肤与配置备份）。
- 现状：全部数据本地化（settings.json、messages、memories），无账号体系；T-40 已有 deviceId（设备绑定），T-42 遥测默认关闭。
- 约束：v1.0（2026-09-01）范围已满；云同步涉及账号/服务端/运维，不宜在 v1.0 硬塞。

## 2. 威胁模型

- 假设：同步服务商不可信，只能接触密文；传输通道 TLS 1.3。
- 服务商可见：密文 blob 大小、块索引、时间戳、设备公钥、IP；应最小化。
- 需要防护：密文篡改（AEAD 认证）、重放/乱序（版本号）、陌生设备接入（设备签名/吊销）、口令丢失（恢复码）。

## 3. 加密方案（建议）

| 环节 | 方案 |
| --- | --- |
| 密钥派生 | 用户口令 → scrypt（N=2^15, r=8, p=1，Node crypto 原生）或 Argon2id（引入 libsodium 时）；每用户随机 salt，KDF 参数版本化 |
| 数据加密 | 每文档随机 256-bit DEK + AES-256-GCM；AAD 绑定 docId 与版本；DEK 由 KEK 包裹（支持密钥轮换） |
| 增量同步 | 按文档加密 + 1MB 分块，只同步变更块，控制流量 |
| 密钥恢复 | 24 词恢复码（BIP39 风格）或加密恢复包；**不提供服务端托管**，忘记口令即数据不可恢复（UI 显著告知） |
| 设备管理 | 每设备 Ed25519 签名密钥对，服务端存公钥；可随时吊销某设备 |
| 冲突策略 | docId/version/updatedAt；last-write-wins + 旧版本保留 30 天 |
| 元数据 | 服务端只存密文 blob、块索引、时间戳、设备公钥，不存明文路径/文件名/内容 |

## 4. 候选服务对比

| 方案 | 托管 | E2EE 适配 | 国内访问 | 说明 |
| --- | --- | --- | --- | --- |
| 自建轻量同步服务 + 国内对象存储（阿里 OSS/Tencent COS） | 自托管 | 完全可控 | 好（国内机房，需备案） | 运维成本高，灵活度最高 |
| Supabase（Pro） | 托管 | 仅存密文可行 | 一般/不稳定 | 自带 Auth/DB/Edge Functions；Pro $25/月含 100GB 存储 |
| Firebase（Blaze） | 托管 | 仅存密文可行 | 差 | Firestore 免费档 1GB/50K 读/20K 写每天；存储 ~$0.15~0.18/GB/月 |
| Cloudflare R2 + Workers/D1 | 托管 | 可行 | 一般 | R2 免费 10GB、出口免费；100GB ≈ $1.5/月 |
| Backblaze B2 | 托管 | 可行 | 差 | 100GB ≈ $0.6/月，出口与 API 另计 |
| WebDAV（坚果云/Nextcloud/自建） | 用户自带 | 完全（本地加密后上传） | 坚果云国内可用 | 零基础设施成本；不适合商业额度产品化 |

## 5. 月成本估算

场景假设：Pro 用户配额 100MB；增量同步为主。

### 1,000 Pro 用户（约 100GB 存储）

| 方案 | 月成本估算 | 构成 |
| --- | --- | --- |
| 自建（国内轻量服务器 + OSS） | ¥100~400 | 服务器 ¥60~100 + 存储 ¥12~20 + 流量（增量为主，峰值另计） |
| Supabase Pro | $25 | 含 100GB 存储与 250GB 出口配额；超出按量 |
| Firebase Blaze | $25~50 | Firestore 存储/读写 + 出口 |
| Cloudflare R2 + Workers | <$10 | R2 100GB ≈ $1.5 + Workers 用量 |
| Backblaze B2 | $2~5 | 存储 + API + 出口 |
| WebDAV（用户自带） | ¥0 | 无基础设施成本 |

### 10,000 Pro 用户（约 1TB 存储）

| 方案 | 月成本估算 | 构成 |
| --- | --- | --- |
| 自建 | ¥300~1,500 | 存储 ¥120~200 + 流量与服务器扩容（流量是主要变量） |
| Supabase Pro | $25 + 超额 ~$20 + 带宽 | 超出 100GB 配额按 $0.021/GB/月 |
| Firebase Blaze | $150~300 | 存储/读写/出口按量 |
| Cloudflare R2 | ~$15 | R2 存储，出口免费 |
| Backblaze B2 | ~$6+ | 存储 + 出口 |

结论：存储不是主要成本，**流量与运维**才是；配额越小、增量同步越省。v1.0 不做云同步时该成本为零。

## 6. 合规与可用性

- 面向国内用户的自建服务需 ICP 备案，并评估《个人信息保护法》要求（数据主体在中国境内）。
- 海外服务商（Supabase/Firebase/B2）对国内用户访问不稳定，需 CDN 或海外节点兜底。
- 隐私政策须披露：同步内容、加密承诺、第三方服务商；同步与遥测相互独立（关闭同步不关闭本地功能）。

## 7. ADR-035 草案（状态：Proposed）

```text
ADR-035（草案）：云同步采用“本地加密 + 服务端密文”，v1.0 不实施

- 状态：Proposed（T-46 评估产出，待协调者/用户评审）
- 背景：Pro 定价含“云同步 100MB”，但 v1.0 无账号体系与服务端；
  云同步属长期承诺，错误实施会引入数据安全与运维风险。
- 决策草案：
  1. v1.0（2026-09-01）不实施云同步，Pro 权益页标注“云同步即将推出”，
     避免承诺未交付功能。
  2. 加密方案定稿：口令派生（scrypt/Argon2id）+ AES-256-GCM 每文档加密
     + 设备签名（Ed25519）+ 恢复码；服务端仅存密文（零知识）。
  3. 服务端候选：优先自建轻量同步服务 + 国内对象存储（阿里 OSS/Tencent COS），
     海外用户备选 Cloudflare R2 或 Supabase；WebDAV 作为“自带存储”试点。
  4. 商业化：云同步仅开放给 Pro/买断用户，配额 100MB，增量同步。
- 后果：Q4 需新增账号与服务端开发任务；官网/商店文案明确“云同步即将推出”。
```

## 8. 建议路线

1. 2026-08（W3 集成期）：按本 ADR 草案向用户确认方向，同步官网措辞。
2. Q4：启动最小验证——WebDAV + 端到端加密（1 个工程师周），验证同步协议与冲突处理；通过后再评估自建服务/对象存储规模化。
3. 上线前完成：隐私政策更新、密钥恢复/设备吊销 UI、配额与限流。
