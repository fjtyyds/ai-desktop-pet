## 验证结论

### ① Web Speech 识别（STT）——不可用（记录降级）

- API 表面存在：`window.SpeechRecognition` 与 `window.webkitSpeechRecognition` 均为 function；`navigator.mediaDevices.getUserMedia({audio:true})` 成功（麦克风采集可用，探针含 fake device）。
- 实测 `recognition.start()`：`start` → `audiostart` 正常触发，约 924ms 后立即 `error: network`，随后 `end`，无任何识别结果。
- 结论：Electron 43/Chromium 的 Web Speech 识别依赖 Google 云语音后端，在 Electron 环境不可用（与 Chromium/Electron 已知限制一致）。
- 降级：聊天面板不显示麦克风按钮，保持文本输入。后续如需语音输入，候选：Windows 原生听写（Win+H）、用户自备云端 STT（需协调者批准依赖/契约扩展）。

### ② 系统 TTS 输出——可用（已落地）

- `window.speechSynthesis` + `SpeechSynthesisUtterance` 在 Electron 43 渲染层可用。
- 系统语音异步加载：`voiceschanged` 后 `getVoices()` 返回 6 个语音，含 Microsoft Huihui（zh-CN）、Microsoft Mark/Zira（en-US）等；朗读“你好”实测 `onend` 正常触发（约 2.4s），speaking 状态正确。
- 落地：src/renderer/chat.js 新增 TTS 能力探测 + 桌宠回复气泡“朗读/停止”按钮（🔊/⏹）：
  - 按界面语言选语音（zh 优先中文语音，en 优先英文语音）；
  - 语音列表未就绪或系统无语音时按钮自动隐藏；
  - 语言切换/清空消息时停止朗读并刷新按钮状态；
  - 文案双语内联（zh-CN/en），不依赖 locale 文件与契约扩展。
- 端到端验证：mock 对话后新回复气泡出现朗读按钮；点击后 `speechSynthesis.speaking=true`、按钮变“⏹/停止朗读”；再次点击停止，`speaking=false`、恢复“🔊/朗读”。

### ③ deepseek-v4-flash 图片消息——不支持（记录降级）

- 真实 API 实测（content 为 `[{type:'text'},{type:'image_url', image_url:{url:'data:image/png;base64,…'}}]`）：
  - HTTP 400：`Failed to deserialize the JSON body into the target type: messages[0]: unknown variant 'image_url', expected 'text'`
  - 同模型/密钥的纯文本控制组返回 200 正常回复。
- 结论：deepseek-v4-flash 只接受文本 content，不接受图片消息；provider/chat/contracts 无需为图片改动。
- 降级：不做图片输入 UI；用户可用“剪贴板文本提问”替代（把图片内容/截图文字粘贴为文本提问）。未来若切换视觉模型，需协调者先修订契约/API.md 并批准 provider/chat/存储改动。
