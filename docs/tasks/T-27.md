## 完成记录（2026-08-10）

- 根因：主进程 `consumePomodoroNotificationRequest` 读取的是 ipc.js 模块缓存的 settings（含未消费信号），清零却经由另一独立 secure-settings 实例写文件，模块缓存未同步；每 2 秒状态轮询都读到同一个陈旧信号，反复弹系统通知。
- 修复：
  - `src/main/ipc.js`：新增 `consumePomodoroNotificationSignal()`——每次从磁盘读最新设置，仅当 `pomodoroNotifyAt > 0` 时经同一 secureSettings 实例清零并同步模块缓存，返回 `{ at, minutes, enabled }`；无信号/清零失败返回 `null`。
  - `src/main/main.js`：`consumePomodoroNotificationRequest` 改为调用上述幂等消费；清零失败或 `pomodoroEnabled === false` 时不弹通知。
  - `src/renderer/chat.js`：`finishPomodoro` 增加 `mode === 'finished'` 幂等守卫；`saveSettings` 明确不携带 `pomodoroNotifyAt`/`pomodoroNotifyMinutes`（注释固化语义）。
  - `src/storage/store.js`：补充一次性信号读写/清理语义注释（仅 patch 显式携带时才写入）。
  - `scripts/check.js`：新增 store 信号写入/保留/清零/不回写陈旧信号断言。
  - `scripts/smoke.js`：预置待消费信号断言首次消费成功、二次消费为 null、缓存清零、普通保存不回写；另跑渲染层 1 秒倒计时 → 主进程消费一次的端到端断言。
- 校验：`npm run check` 通过；`npm run smoke` 通过（真实用户权限，含 2 组 pomodoro 回归断言）。
- 人工目检：待人工目检（系统通知弹窗需真实桌面环境；smoke 已覆盖渲染层 → 主进程信号链路，建议协调者验收时以 1 分钟番茄钟复核只弹一次）。
